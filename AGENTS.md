# AGENTS.md — working on zotero-refs with an AI agent

Contract for any change: `npm run build` must pass (esbuild + `tsc --noEmit`), the plugin must load in a **Zotero 7–10** main window (tested on 9.0.6 and 10.0; Zotero 10 keeps the Firefox 140 base and only removed singular-selection APIs / `Zotero.CookieSandbox` / `fulltextWord`, none of which we use) without a single uncaught exception, and the four item-pane sections (References / Cited By / Related / Citation Graph) must render for a normal journal article. Never test against the user's real Zotero profile — always the isolated dev profile (below).

## Build & dev loop

```bash
npm run build     # production xpi -> .scaffold/build/refs.xpi (also runs tsc)
npm start         # dev build + hot reload in an ISOLATED Zotero profile
```

`.env` (copy from `.env.example`) points at the Zotero binary and pins profile/data dirs under `.scaffold/`; the kill command is scoped to the dev profile path so a running production Zotero is never touched.

**Closed-loop debugging**: dev builds register a localhost eval endpoint (`POST http://127.0.0.1:23124/refs-dev/eval`, JSON `{token, code}`, token in `src/modules/devEval.ts`). `code` runs as an async function body with `Zotero` and `addon` in scope inside the dev instance — use it to select items, inspect DOM, read `Zotero.getErrors(true)` and `Zotero.Debug.get()`. It is compiled out of production builds via the `__env__` check. FTL (localization) changes are NOT hot-reloaded — restart the dev Zotero. After several hot reloads the item pane can hold zombie section instances from previous plugin versions; restart before trusting DOM-level verification.

## Architecture (src/)

- `core/types.ts` — shared contracts (`RefItem`, `Identifiers`, `MetaSource`, graph types, `SOURCE_BADGE`).
- `core/http.ts` — all network IO: per-host LIFO gates (newest hover wins), byte-budgeted LRU cache, retry with `Retry-After`.
- `core/text.ts` — pure text utils: identifier extraction, `normalizeTitle`, raw-citation parsing (`parseRefText`).
- `core/libmatch.ts` — `LibraryIndex`: O(1) in-library matching maps (DOI/arXiv/PMID/title), incremental notifier updates.
- `core/storage.ts` — per-item persistent cache (`refs-cache.json`); strips `libItemID` before persisting (deliberate).
- `core/importer.ts` — import a reference into the library + bidirectional relation.
- `sources/` — one module per metadata source (crossref, semanticscholar, openalex, arxiv, pubmed, unpaywall, cnki, readpaper) + `index.ts` registry with fallback chains.
- `core/fuse.ts` — fuses the PDF parse (skeleton: order, numbering, text, anchors) with the API list (metadata, DOIs) into the single list the panel shows. Matching keys: identifier equality > title (≥25 normalized chars + year + first author, unique) > vol/first-page > verified position (Crossref only). Validated on a 699-paper corpus: 83.9 % of entries matched, DOI coverage 19 %→80 %, zero DOI-contradicted matches in a decoy test.
- `pdf/parser.ts` — PDF text-layer bibliography parser (ported from zotero-reference, AGPL).
- `pdf/readerLinks.ts` — reader integration on Zotero 7+'s overlay pipeline (`_onSetOverlayPopup`, `navigate` wrap, split-view jump).
- `ui/` — `section.ts` (References panel), `citations.ts`, `related.ts`, `graphSection.ts`, `rows.ts` (shared row + hover card), `popup.ts`, `styles.ts` (single injected stylesheet).
- `graph/` — OpenAlex graph data build + d3-force SVG view.
- `hooks.ts` — lifecycle; every startup step individually guarded.

## Hard-won invariants — violate these and the plugin breaks in ways that took real debugging to find

1. **Zotero calls plugin ItemPane hooks with NO try/catch.** One exception aborts Zotero's own itemDetails render loop and wedges `_isRendering`, killing NATIVE sections too. Every hook body must stay wrapped in `guard()` / `guardAsync()` (`src/utils/guard.ts`).
2. **Fluent messages used as `data-l10n-id` on section header/sidenav must be attribute-form** (`.label` / `.tooltiptext`). A value-form message makes Fluent REPLACE the element's children, gutting Zotero's collapsible-section DOM.
3. **FTL message ids must NOT start with the addonRef prefix (`refs-`)** — the build tool skips prefixing ids that already look prefixed, silently breaking `getString`. Use `panel-*`, `menu-*`, `pref-*`, `graph-*`.
4. **Title matching must never use mid-string containment.** Two real bugs shipped from this: Crossref title search matched "Review of X" derivatives, and the library matcher matched an item titled "Small-cell lung cancer" to any ref mentioning "non-small-cell lung cancer". Current rules: API `titleSimilar` = strict normalized equality; `libmatch` fallback = shared-prefix ≥ 25 normalized chars + publication-year corroboration. Keep it strict; false negatives are cheap, false positives corrupt user data (wrong import/relation).
5. **CSS: never use the `background` shorthand on `.references-button`** (or anything carrying an icon class) — the shorthand resets `background-image` and blanks the toolbar icons. Use `background-color`.
6. **Citations paging pins the first successful source** (S2 vs OpenAlex) and dedupes across pages via a seen-set keyed by DOI/S2/OpenAlex-id/normalized title. Mixing sources across pages produces duplicates.
7. **`item.getField()` can throw `UnloadedDataException`** on items from `Zotero.Items.getAll` — always per-item try/catch in library-wide loops.
8. **Reader integration must go through the overlay pipeline** (`_onSetOverlayPopup` + `navigate` wrap). The pdf.js annotation layer is hidden in Zotero 7+ (`display:none`) and `reader.menuCmd` / `secondViewIframeWindow` no longer exist in Z9. Teardown must restore every monkey-patched original and sweep closed readers.
9. **zotero-plugin-toolkit ≥5**: no `ZoteroToolkit` main export, no `ztoolkit.Menu`. We compose `MyToolkit` from BasicTool/UITool/ProgressWindowHelper/ClipboardHelper and use the native `Zotero.MenuManager` (Z8+) with a DOM fallback for Z7.
10. **AGPL-3.0**: the PDF parser is ported from AGPL zotero-reference — the project cannot be relicensed permissively. Keep the license header intact.
11. **URLs from outside are hostile.** Anything that came from a PDF (`unsafeUrl`), a remote API, or the cache file must pass `isHttpUrl()` (core/text.ts) before it is persisted, written into an item, or handed to `Zotero.launchURL` — Zotero forwards file:/smb:/custom schemes to the OS. `storage.ts` re-sanitizes every ref on load and save.
12. **Never `await` a settle-delay or a network fetch inside `onAsyncRender`.** Zotero awaits each pane's asyncRender in sequence; schedule the fetch with `setTimeout` and return. Item-switch detection = the render's `list.isConnected` (the shared body is wiped by every render).
13. **Icons are `context-fill` / `context-stroke` SVGs** (16px header, 20px sidenav under `icons/20/`, 1px / 1.25px on the pixel grid, no dark twins). Zotero's `.btn[custom]` and `collapsible-section[custom] .head .title::before` supply `-moz-context-properties`; our own toolbar buttons set them in styles.ts.
14. **Host identifiers come from `hostIdentifiers(item)`** (DOI field/Extra, PMID/arXiv from Extra/URL) — never read `getField("DOI")` alone in a section; PubMed-imported items have no DOI field.
15. **Batch imports go through `runBatchImport`** (confirmation + click-to-stop). Never call `importAll` from a UI path directly.
16. **API titles carry HTML** (`<i>ALK</i>`, `&amp;`, newlines inside tags). Every source mapper passes title/venue/unstructured text through `cleanText()` (core/text.ts) and `storage.ts` re-cleans on load; UI code that shows a ref title must never assume it is plain.
17. **PDF parser: numbering beats geometry.** `mergeSameRef` first tries `mergeNumberedRefs` — an entry starts iff the line begins with the NEXT number in sequence (`numAtStart`: "12." "12)" "[12]" "(12)" "12 Author", JAMA's "12 . Author", Chinese "33 ．Lin"; bare numbers must be followed by a letter/quote so wrapped volume fragments "41 , 1103" and table cells "25 (12%)" don't count). Numbers set in the margin as their own text run (BMJ Fast Facts) are glued to the entry text in `mergeSameLine` — kept narrow on purpose (a general band-overlap rule merges the page number into the running head and breaks header/footer removal). Geometry/indent merging is only the fallback for unnumbered lists — and for blocks whose numbering is out of sequence (OCR'd scans). The no-heading fallback is gated on publication years (≥50% of entries carry a 19xx/20xx). `getRefLines` walks pages backwards **to page index 0**; after the heading page it completes the heading page and appends later pages whose union of lines picks up the sequence, ignoring false headings ("References (160–200)") and the "skip until bottom-right line" heuristic when the running footer leads the stream.
    **The content stream is not reading order** (v1.0.11): figures, axis labels, captions, running heads/footers and corner logos are routinely drawn AFTER the body text, so the lines after an entry in the stream can sit anywhere on the page (JAMA Guide: 45 lines of axis labels glued to the last reference). Two defences, both geometric — do not replace them with text heuristics:
    (a) **Heading-page completion is spatial.** A line of the heading page counts as "after the heading" only if it is below the heading inside the heading's column band and chained to the block without a block-sized gap (footers fail), or sits in a column to the right of the heading's AND that right-hand block continues the bibliography (picks up the numbering / ≥50% dated entries / a justified text column with ≥1 year line per 7 — NEJM 2006 sets its numbers as separate runs so the merge over-splits). Stream-column index ≠ reading order.
    (b) **`continuationVerdict` decides whether a line may continue the current entry:** later page → yes; below the previous line in the same column band (|Δx| < 5 line heights, gap < 4.5 — double-spaced manuscripts) → yes; above it and clearly to the right → the next column (rejected when it is a ≤3-character run such as Cell's "ll" logo; for the LAST entry also rejected after a stray line or when the line is not column-width); anything else is a stray line — dropped, the entry continues with its next plausible line. Lines accepted through the page-change/column-jump rules are PROVISIONAL: the first line of a new page is as often a running head as the entry's continuation; when a later line does not follow the provisional run but does follow the last solid anchor (and is a real column line), the run was the running head — it is retracted (NEJM "Alectinib vs. Crizotinib…", Am J Cancer Res footers, JCO "© 2016 by ASCO" mid-entry all disappear this way). Tail noise is split in two: block headings (`TAIL_HEADING`: acknowledgements, contributions, disclosures, supplementary, figure/table legends, 致谢/基金项目…) end the list wherever they are; boilerplate (`TAIL_BOILER`: open access, ©, licensee, publisher's note, downloaded from, accepted article…) ends it only when it opens a block directly below the entry, below the last entry, or on a later page once the entry reads as complete (`ENTRY_END`: page range / vol:pages / DOI / URL / PMID / e-locator / "]" — deliberately not a bare year, titles end in years); a lone boilerplate line between the two halves of an entry (Wiley "Accepted Article" watermark) is dropped. Both lists are also matched with whitespace removed ("AC KNOWLED GME NTS"). The last entry is additionally closed when it reads complete and the next line starts like a new block, and capped at 12 wrapped lines. Nothing in TAIL_HEADING/TAIL_BOILER may plausibly start a wrapped line inside an entry ("licensed doses…", "Competing feedback loops…", "Published online…" were all real false positives — that is why `licen[cs]e` and bare `competing` are gone).
    **Manuscript line numbers** (v1.0.11): submitted/accepted manuscripts, pre-proofs and JITC/Nature author versions carry "427 428 429…" down a margin as bare-integer text runs; merged into the lines they corrupt entry numbers ("456 1 0 . Hosny A") and text ("…RGPM, 454 Granton P"). `findLineNumbers` drops them per page — a margin x-cluster (left- or right-aligned) of ≥ 8 bare integers, ≥ 80 % consecutive, beside ≥ 60 % of the page's text lines — but ONLY when `hasLineNumbers` has found such a column on a body page first (it probes pages 1, 2, 3, n/4, n/3). Never decide on the bibliography page itself: a review's one-line references with bare margin numbers look exactly the same (YLMGWAHK went 189 → 15 before the gate), and probing the second half of the document hits the bibliography. BMJ/JAMA entry numbers in the margin fail the coverage test (one number per 3–4 lines). `compactLeadingDigits` closes "1 0 ." → "10." only before the number's punctuation — a bare "1 7 insight.jci.org" is a spaced page number and once became entry 17.
    **Which bibliography** (v1.0.11): a late list is not necessarily THE list — manuscripts append a separately numbered "Methods References"/"Supplementary References"/"eReferences", bundled supplements carry a three-entry "REFERENCES", a table column says "Reference". When the heading found first (walking backwards) is qualified (not a plain References/Bibliography/参考文献/References and Notes, optionally "4." numbered) or the block is tiny (< 6 numbered starts and < 40 lines), the walk stashes it and continues; an earlier list replaces it if it is plain AND carries years (≥ 15 % of lines) AND (the stash was qualified OR it is ≥ 2× longer). Otherwise the stash is restored. Judge "tiny" on numbered starts, not lines — the walk splits a double-spaced heading page into parts that the completion step only adds later (PGIEIW5X: 3 lines at that point, 13 entries after completion).
    **Page-level continuation must advance `lastNum`** (v1.0.11): the byPage step appends later pages whose union picks up the numbering; it compared every page against the HEADING page's last number, so only the first continuation page ever joined. Cell Press / JAMA Network Open / Nature Reviews lists were silently truncated for years (Zhu 2025 Cancer Cell 56 → 87, She 2020 JAMA Netw Open 36 → 48 = Crossref, DeSantis 2014 87 → 107 = Crossref, Hendriks 2024 Primer 218 → 278). If a parser change ever makes many counts move by tens, this is the first place to look.
    Regression: `scripts/parser-corpus/` (dev-instance harness, 32 journals, 24/27 exact vs Crossref) and the offline harness in git-ignored `.corpus/offline-harness/` (Node + pdfjs-dist, no Zotero; runs the whole ~700-PDF library in ~3 min, A/B old vs new parser — `results/baseline-1.0.10.json` vs `results/parser-2026-08-23.json`: ~260 PDFs changed, every change reviewed, several counts confirmed against Crossref; suspicious-tail files 96 → 23; total parsed references 38 119 → 39 630).
18. **CNKI credential POST must pass `logBodyLength: 0`** — Zotero's debug-log redaction is case-sensitive and misses `"Password"`.
19. **The References panel shows ONE fused list; the PDF/API mechanism stays hidden.** No source switch in the UI: `section.ts` fetches both sides in parallel (PDF only with an open reader), fuses via `core/fuse.ts`, names the contributors next to the count ("PDF + Crossref"), and caches the raw layers under the `PDF`/`API` slots plus the shown list under `FUSED` (row edits persist there; cache-first loads `FUSED`, then composes offline from the raw slots). Whichever side is missing, the other alone must still render. Fusion must never drop or reorder PDF entries; identifiers printed in the PDF win, but structured API metadata (title/authors/year) beats the parse's text-guess; the API-only tail is appended only when the API list is genuinely longer than the parse (equal-length remainders are the same entries pairwise — appending would duplicate them).
20. **The plugin accent is the Zest light green.** `--refs-accent` (#40c463) with `--refs-accent-strong` / `--refs-accent-wash` derivatives is defined once in `styles.ts` on `:root`; plugin UI draws from these tokens (never Zotero's selection-blue `--color-accent`, never new hex literals). The popup's source dots (#2da44e active / #b5e6c4 idle) and the graph's origin node (#2da44e) follow it; the popup TITLE keeps its classic blue (user said so), and source badges / the retracted red stay semantic.
21. **Every user-visible string goes through `getString()`/FTL in BOTH locales** (en-US + zh-CN, same keys). Raw API field names (`is-referenced-by-count`, `citationCount`, `cited_by_count`) must never surface in tooltips or labels — the cited-count chip uses `tag-cited-tip` with the source as an argument and the shared `CITED_CHIP_COLOR`. ProgressWindow headlines/lines, importer/parser status text and source-badge tooltips are FTL-backed too (`SOURCE_BADGE.tip` is only the fallback when a `source-tip-*` key is missing). New FTL ids need `npm run build` to regenerate `typings/i10n.d.ts`.
22. **Reader citation popups are ours when we're confident, Zotero's otherwise.** The Zotero 10 reader extracts the printed bibliography itself and calls `_onSetOverlayPopup` with `citation`/`reference` overlays carrying `references[{ text, index?, position }]`; `readerLinks.ts` wraps that hook (same pipeline since Z7, re-verified against the 10.0 bundle). Takeover rules: single-entry overlays match by entry number + normalized-prefix agreement (never containment), anchor-nearest is the fallback (internal-link overlays carry no text), multi-entry clusters and failed matches keep the native popup untouched. The reader keeps its own list when the panel hasn't rendered — `FUSED` cache slot first (anchors + API enrichment), then `PDF`, then one parse — and the tab focused at startup is primed from `attachAllReaders` (it never fires a tab-select notification). The reader card passes `onImport` (deduped by `libraryIndex.match` inside `importReference`). Popup placement must hop the chrome boundary via `reader._iframe.getBoundingClientRect()`: in Zotero 10 `frameElement` (and `browsingContext.embedderElement`, hidden by the sandbox wrapper) dies at the reader `<browser>` element, which silently reverted every hover card to the native preview until 1.0.15. Detached reader windows still return null → native preview. The dev build carries an end-to-end self-test (devEval.ts, runs on every dev boot with an open PDF tab, writes `dev-data/dev-eval-status.log`) that proves takeover / pass-through / multi-cluster behavior.

## Releasing (auto-update depends on this exact shape)

`manifest.json` → `update_url` = `https://github.com/yimmy23/zotero-refs/releases/download/release/update.json` (a **rolling** GitHub release tagged `release` holds `update.json` / `update-beta.json`). Zotero only offers an update when the version in `update.json` is **higher** than the installed one and the `update_link` asset exists with a matching sha512 — so never re-upload a changed xpi under the same version.

1. bump `version` in `package.json` (semver) → `npm run build` (emits `refs.xpi` + `update.json` with the hash)
2. `gh release create vX.Y.Z .scaffold/build/refs.xpi --title "Refs X.Y.Z" --notes "…"`
3. `gh release upload release .scaffold/build/update.json .scaffold/build/update-beta.json --clobber`
4. verify: `curl -sL <update_url>` shows the new version; in the dev profile install the previous xpi and run `AddonManager` `findUpdates` → `updateAvailable` (see session notes for the probe).

## Testing checklist for non-trivial changes

Run in the dev instance via the eval endpoint: select a DOI-bearing item → References section fills (count line shows source), toolbar icons visible (computed `background-image` ≠ none); hover a row → card appears with source dots and identifier/search chips; `+` imports the CORRECT item and relates it bidirectionally; Cited By pages without duplicates; Graph renders nodes ≈ `graphMaxNodes` cap; `Zotero.getErrors(true)` shows nothing from the plugin. For zh-CN strings, restart (FTL) and verify no raw message ids leak into the UI.
